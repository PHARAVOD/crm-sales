# Журнал дефектов CRM системы

## Дефект #1: При ошибке оплаты заказ остается в статусе New

| Поле | Значение |
|------|----------|
| **ID** | DEF-001 |
| **Серьезность** | Критический (High) |
| **Приоритет** | Высокий (High) |
| **Обнаружен** | 2026-05-31 |
| **Модуль** | Saga Orchestrator |

### Описание
При превышении лимита оплаты (сумма > 150 000 руб) заказ не переходит в статус Failed/Cancelled, а остается в статусе New.

### Шаги воспроизведения
1. Добавить товар в корзину на сумму 200 000 руб
2. Нажать "Оформить заказ"
3. Оплата отклоняется (лимит)
4. **Результат:** Заказ остается в статусе New

### Ожидаемый результат
Заказ должен перейти в статус Failed → Cancelled

### Локализация причины
В коде Saga Orchestrator отсутствовал вызов компенсации при ошибке оплаты. Исключение перехватывалось, но компенсация не выполнялась.

### Исправление
Добавлен блок компенсации в обработчик ошибок:
- Возврат средств
- Отмена резервирования товаров
- Перевод заказа в статус Cancelled

### Статус
✅ **ИСПРАВЛЕН**

## Дефект #2: Проверка остатков не срабатывает при нулевом количестве

| Поле | Значение |
|------|----------|
| **ID** | DEF-002 |
| **Серьезность** | Высокий (High) |
| **Приоритет** | Высокий (High) |
| **Обнаружен** | 2026-05-31 |
| **Модуль** | Stock Service |

### Описание
При заказе товара с остатком 0 шт, проверка остатков возвращает Success.

### Шаги воспроизведения
1. Заказать товар с ProductId = 999 (остаток 0)
2. Проверить результат проверки остатков

### Причина
В методе проверки остатков отсутствовала проверка на нулевое количество.

### Исправление
Добавлена проверка:
- Если количество товара == 0 → ошибка "Товара нет в наличии"
- Если количество > 0 → нормальная проверка

### Статус
✅ **ИСПРАВЛЕН**

## Дефект #3: State Machine допускает некорректные переходы

| Поле | Значение |
|------|----------|
| **ID** | DEF-003 |
| **Серьезность** | Средний (Medium) |
| **Приоритет** | Средний (Medium) |
| **Обнаружен** | 2026-05-31 |
| **Модуль** | Order State Machine |

### Описание
State Machine позволяет перейти из статуса New в Delivered напрямую, минуя Paid и Shipped.

### Шаги воспроизведения
1. Создать новый заказ (статус New)
2. Попытаться перевести сразу в Delivered

### Причина
В правилах переходов были разрешены некорректные переходы.

### Исправление
Обновлены правила переходов:

| Из статуса | Разрешено в |
|------------|-------------|
| New | Paid, Cancelled |
| Paid | Shipped, Cancelled, Failed |
| Shipped | Delivered, Cancelled |
| Failed | Cancelled |
| Cancelled | (нет переходов) |
| Delivered | (нет переходов) |

### Статус
✅ **ИСПРАВЛЕН**

## Дефект #5: UI не обновляется после отмены заказа

| Поле | Значение |
|------|----------|
| **ID** | DEF-005 |
| **Серьезность** | Средний (Medium) |
| **Приоритет** | Средний (Medium) |
| **Обнаружен** | 2026-05-31 |
| **Модуль** | Frontend (JavaScript) |

### Описание
При ошибке оформления заказа UI не показывает сообщение об ошибке.

### Шаги воспроизведения
1. Оформить заказ на сумму > 150 000 руб
2. Оплата отклоняется
3. **Результат:** UI показывает "Обработка", нет уведомления об ошибке

### Причина
В JavaScript коде отсутствовал обработчик ошибок.

### Исправление
Добавлен блок catch с:
- Отображением сообщения об ошибке
- Обновлением статуса заказа
- Показом уведомления пользователю

### Статус
✅ **ИСПРАВЛЕН**
